## Summary

This release keeps the `.26` tsnet status Web improvements and adds two operational conveniences:

- a protected controller API to persist a custom embedded tsnet node name for the next restart
- a Windows best-effort firewall helper for the embedded tsnet userspace WireGuard path

The release does not change persistent-pin behavior, proxy group behavior, routing, DNS, gateway SOCKS semantics, mesh SOCKS semantics, login-server fallback, or the read-only status API fields.

## What Changed

### Protected Node Name Override

A new controller endpoint is available:

```text
PATCH /tailscale/node-name
```

Request body:

```json
{"name":"mihomo-home"}
```

Behavior:

- The endpoint reuses the existing external-controller Bearer secret protection.
- It writes the requested name to `state-dir/node-name`.
- The custom name takes precedence over the generated `mihomo-<short-id>` name on the next tsnet runtime startup.
- The active runtime is not restarted by the endpoint.
- The name must be a single DNS label: `1..63` ASCII letters, digits, or hyphens, with no leading or trailing hyphen.
- Invalid JSON, invalid names, or missing active tsnet runtime return `400`.

This is intended for users who share one YAML across many machines but still want each state-dir backed embedded tsnet node to have a stable, human-friendly name.

### Windows Firewall Helper

Windows builds now include a platform hook that runs after tsnet reaches `connected`:

- It deletes any existing firewall rule named `Mihomo-Tailscale-WireGuard`.
- It adds a Windows Defender Firewall allow rule for the current mihomo executable path.
- If Administrator rights are required and the command fails, mihomo logs a warning and prints the equivalent manual `netsh advfirewall firewall add rule ...` command.
- On runtime close or reload, it deletes the same rule name.
- Non-Windows builds compile no-op hooks.

This helper is best-effort. Failure to add the rule does not disable tsnet or the main mihomo process.

## Behavior Changes

- `stableNodeName` now checks `state-dir/node-name` before falling back to the generated `mihomo-instance-id` based name.
- `PATCH /tailscale/node-name` is a write endpoint. The existing `/tailscale`, `/tailscale/logs`, and `/tailscale/web` status surface remains unchanged.
- Windows can receive an automatic firewall rule once tsnet connects.

No changes to:

- persistent pin runtime behavior
- url-test or fallback group selection
- proxy parsing or provider behavior
- ordinary SOCKS, HTTP, TUN, or DNS behavior
- tsnet login-server IP fallback behavior
- registration wizard behavior
- gateway SOCKS TCP/UDP forwarding behavior
- tailnet mesh SOCKS TCP/UDP forwarding behavior
- controller exposure over tailnet
- release workflow or Docker-disabled policy

## Manual Smoke Checks

Node rename API:

```bash
curl -i \
  -X PATCH \
  -H 'Authorization: Bearer <secret>' \
  -H 'Content-Type: application/json' \
  --data '{"name":"mihomo-home"}' \
  http://127.0.0.1:9090/tailscale/node-name
```

Expected:

- valid name returns `204`
- invalid names such as `-bad`, `bad/name`, or an overlong label return `400`
- after restart, logs show the custom `node-name`

Windows firewall helper:

- Start a Windows build with `tailscale.enable=true`.
- Wait until tsnet reaches `connected`.
- Confirm logs either show the rule was added or print the manual `netsh` command if not elevated.
- Reload or stop mihomo and confirm the rule with the fixed name is removed.
