## Summary

This release keeps `.24` runtime behavior and improves only the built-in read-only tsnet Web page plus repository documentation.

The peer table now has a hover detail popup for quickly inspecting a peer without widening the table or exposing additional backend endpoints. The static-shell safety model remains unchanged: `/tailscale/web` embeds no runtime data, and all peer/status/log data is still fetched through the controller-protected APIs.

## What Changed

- Added a peer hover popup on `/tailscale/web`.
- Popup details include DNS name, OS, tail IPs, primary routes, tags, state, relay, endpoints, current address, allowed IPs, traffic, peer API URLs, timestamps, key expiry, public key, and peer ID when available from the protected `/tailscale` API.
- The popup follows the mouse and stays within the viewport.
- The popup is hidden and reset whenever the peer table is re-rendered by search, sorting, refresh, or auto-refresh.
- Self node metadata now shows DNS name, endpoints, last handshake, public key, and ID when available.
- Added historical release notes for `.24` and updated tsnet documentation for the Web UI detail popup.

## Behavior Changes

Only the static read-only Web page changed.

- No backend behavior changes.
- No change to persistent pin behavior.
- No change to tsnet startup, registration, login-server fallback, gateway, mesh SOCKS, controller exposure, UDP behavior, DNS, rules, or groups.
- No change to `/tailscale` or `/tailscale/logs` API shape.
- No config, state-dir, or identity migration.
- `/tailscale/web` remains a static shell and continues to fetch runtime data through the protected controller API.
