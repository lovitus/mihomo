## Summary

This release builds on `.18` and focuses on the read-only tsnet status surface. It adds the Tailscale daemon/library version to the protected status API and makes the built-in Web page more useful for inspecting peers without changing runtime behavior.

The Web shell remains public and static. Runtime data, including auth URLs, peers, node keys, tail IPs, diagnostic paths, and logs, is still loaded only from the controller-protected API.

## What Changed

- `/tailscale` now includes `daemonVersion` when `LocalClient.Status(ctx)` provides a version.
- The Web page shows daemon version in the diagnostic section.
- The peer table supports sorting by name, OS, state, relay path, and last activity.
- Peer rows now distinguish direct connections from relay paths.
- Peer rows display tags, shared-node markers, exit-node markers, near-expiry key hints, sorted tail IPs, and a clearer last-active timestamp.
- The page shows the last refresh time after each successful API load.
- Offline peers are visually de-emphasized while remaining visible in the same table.

## Behavior Changes

No tsnet runtime behavior changes.

The status API remains read-only and fail-soft:

- live status query failure still returns HTTP `200` with `statusError`
- disabled/runtime-nil state still returns the minimal disabled status
- logs are still in-memory only
- `/tailscale/web` still serves only a static shell

## Compatibility

- No config migration.
- No state-dir migration.
- No change to persistent pin behavior.
- No change to tsnet startup, gateway, mesh SOCKS, controller exposure, or UDP behavior.
- No change to mihomo rule, group, DNS, HTTP, DIRECT, or ordinary SOCKS5 behavior.

## Manual Smoke Checks

With controller secret enabled:

```bash
curl -i http://127.0.0.1:9090/tailscale
curl -i http://127.0.0.1:9090/tailscale/logs
curl -i -H 'Authorization: Bearer <secret>' http://127.0.0.1:9090/tailscale

```

Expected result:

- unauthenticated API calls return `401`
- authenticated API calls return `200`

- page source does not contain runtime peer data, `authURL`, `stateDir`, `nodekey:`, or log bodies
