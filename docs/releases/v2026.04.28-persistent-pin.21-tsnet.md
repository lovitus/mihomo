## Summary

This release fixes a status-display edge case for Headscale networks that use non-standard node IPv4 ranges such as `10.x.x.x`. In those deployments, Tailscale may omit the peer node IPv4 from `PeerStatus.TailscaleIPs` because it is not inside the built-in Tailscale address range. The protected `/tailscale` API now augments peer IPs from single-host `AllowedIPs` while avoiding advertised primary routes.

The built-in Web page also renders self and peer IPs one address per line for easier scanning.

## What Changed

- `APIPeerStatus.tailscaleIPs` now includes missing single-host peer addresses from `AllowedIPs`.
- Advertised `PrimaryRoutes` are excluded from that augmentation so routed host prefixes are not mistaken for the peer's own node address.
- IPv4 single-host additions are ordered before existing peer IPs to match the UI's IPv4-first display.
- Self node IPs use top-level `tailIPs` when available.
- Self and peer IP lists render one address per line instead of relying on newline text escaping.

## Behavior Changes

Only the read-only status API and Web rendering changed.

- No tsnet dial/listen behavior changed.
- No gateway, mesh SOCKS, controller exposure, UDP, DNS, rule, or group behavior changed.
- No config, state-dir, or identity migration.
- `/tailscale/web` remains a static shell and continues to fetch runtime data through the protected API.
