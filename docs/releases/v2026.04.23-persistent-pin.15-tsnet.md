## Summary

This release keeps the `.14` runtime behavior and release documentation, then fixes the independent GitHub `Test` workflow failure observed on the `.14` tag.

The failure was in test timing only. Some GitHub macOS and ARM runners observed `runtime.closed=true` before `Close()` had finished its deferred cleanup and called `endResolverLifecycle()`. The test asserted the resolver lifecycle immediately after seeing `closed`, so it could fail even though cleanup completed moments later.

## What Changed

- `component/tsnet/tsnet_test.go` now waits until `DefaultResolverFailClosed()` becomes false after watchdog-triggered close.
- The test still verifies the same behavior: watchdog timeout disables the runtime, clears `current`, releases the resolver lifecycle, and releases the state-dir lock.
- No runtime code changed.

## What Was Fixed

Fixed flaky CI failures in:

- `TestStartupWatchdogTimeoutDisablesRuntimeAndReleasesLock`

Observed failing environments on `.14` included:

- `macos-latest` with Go 1.24/1.25
- `macos-26-intel` with Go 1.22/1.23/1.25
- `ubuntu-24.04-arm` with Go 1.23/1.26

Failure symptom:

```text
resolver lifecycle still active after watchdog close
```

Root cause:

- `runtime.Close()` sets `closed=true` before waiting for `runDone`, closing listeners, closing the server/lock, and ending the resolver lifecycle.
- The test used `closed` as a proxy for full cleanup completion.
- On slower or more concurrent CI runners, that proxy was too early.

Fix:

- Keep waiting after `closed=true` until the resolver lifecycle guard is actually inactive.

## Behavior Changes

No runtime behavior changes.

The `.14` tsnet UDP fallback documentation remains accurate:

- no tailnet identity lookup for unspecified UDP BND.ADDR
- no MagicDNS relay-address resolution expansion
- tsnet UDP miss falls back to the original default path

## Abnormal Path Handling

Runtime abnormal-path handling is unchanged from `.14`.

Test abnormal-path handling is improved:

- watchdog close is still allowed to happen asynchronously
- tests wait for the cleanup condition they assert
- transient runner scheduling differences no longer turn a correct close into a false negative

## How To Use

No user-facing configuration changes.

Use the same tsnet config documented in `.14` and `docs/tailscale-tsnet.md`.
