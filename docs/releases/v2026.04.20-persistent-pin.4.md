## What This Release Is

This release upgrades the fork from the old persistent pin release lineage onto upstream `MetaCubeX/mihomo` `v1.19.24`, while preserving the fork-specific behavior that was previously released as:

- `v2026.03.13-persistent-pin.1`

It is not a new feature branch with a different behavior contract.

## Runtime Behavior Preserved in This Release

### 1. `fallback` group behavior

- Still chooses the first alive proxy in original order
- Does not return a timeout or unhealthy node when another alive node exists
- Supports `persistent-pin: true`
- Does not silently release a persistent pin during automatic checks
- Clears a missing pinned proxy with warning
- Supports auto-unfix after threshold
- Resets auto-unfix counter when:
  - pinned proxy recovers
  - newer successful test records exist
  - no alternative alive proxy exists
  - selection changes manually

### 2. `url-test` group behavior

- Does not select timeout or unhealthy nodes when alive nodes exist
- Keeps persistent pin effective during automatic refresh
- Refreshes cached routing state after manual `URLTest()`
- Clears a missing pinned proxy with warning
- Matches `fallback` for auto-unfix and reset semantics

### 3. Shared group health semantics

- `GroupBase.URLTest` only records healthy valid results
- Delay leftovers alone do not make an unhealthy node look healthy

### 4. Config surface preserved

Still supports:

```yaml
persistent-pin: false
pin-unhealthy-log-interval: 10
persistent-pin-auto-unfix-threshold: 10
```

Validation semantics preserved:

- `pin-unhealthy-log-interval < 0` is invalid
- `pin-unhealthy-log-interval: 0` is not parser-invalid and still results in constructor default `10s`
- explicit `persistent-pin-auto-unfix-threshold <= 0` is invalid
- unset `persistent-pin-auto-unfix-threshold` still uses fork default

### 5. API behavior preserved

- `/groups/{name}/delay` does not clear persistent pin when the target group has `persistent-pin=true`

### 6. Logging preserved

Still includes:

- unhealthy pinned-proxy warning
- warning with auto-unfix counter state
- missing pinned-proxy warning
- reset log with reason
- auto-unfix log with reached count
