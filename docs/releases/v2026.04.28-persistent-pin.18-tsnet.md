## Summary

This release keeps the `.17` read-only tsnet status API and built-in Web page, then tightens runtime retry behavior and improves the one-page status UI.

The main runtime changes are defensive: gateway TCP listen failures now retry with bounded backoff, and the startup path tolerates a short gap between Tailscale reporting `Running` and the local status call returning tail IPs. The Web page remains a static public shell and continues to fetch all sensitive runtime data only through the controller-protected API.

## What Changed

- Gateway SOCKS5 TCP listen failures are retried in the background instead of staying failed until reload.
- Retry backoff is capped at `5m` to avoid unbounded delay growth.
- Startup waits briefly for tail IP assignment after backend `Running` status before declaring startup failure.
- The global unused `userLogf` helper was removed; runtime-bound `UserLogf` remains the active path.
- The built-in tsnet Web page was simplified into a lighter single-page layout while preserving full status, peer, service, diagnostic, and log visibility.
- The Web page keeps light styling only and uses user-facing wording for clearing the saved controller token.
- Static HTML still avoids embedding `authURL`, `stateDir`, node keys, tail IPs, peer data, or logs.

## Behavior Changes

Gateway behavior:

- If `tailscale.gateway-socks5` is enabled but the host TCP port is temporarily unavailable, mihomo logs the failure and keeps retrying with bounded exponential backoff.
- When the port later becomes available, the gateway listener is installed without requiring a full mihomo reload.
- Gateway UDP setup is still best-effort after TCP listener creation. If UDP bind fails, UDP ASSOCIATE is rejected explicitly.

Startup behavior:

- After the tsnet backend reports `Running`, mihomo now retries `LocalClient.Status(ctx)` up to 3 times with a `500ms` interval if no tail IP is visible yet.
- If no tail IP is available after those retries, startup still fails with `register-failed` as before.
- Request cancellation is respected while waiting between retries.

Web/API behavior:

- `/tailscale` and `/tailscale/logs` remain protected by the existing controller Bearer secret.
- `/tailscale/web` remains public but contains only the static shell.
- The Web page stores the entered controller secret in browser `sessionStorage` only.
- The page supports refresh, auto-refresh, peer filtering, auth URL copy, and clearing the saved token.

## Manual Smoke Checks

With controller secret enabled:

```bash
curl -i http://127.0.0.1:9090/tailscale
curl -i http://127.0.0.1:9090/tailscale/logs
curl -i -H 'Authorization: Bearer <secret>' http://127.0.0.1:9090/tailscale
curl -i -H 'Authorization: Bearer <secret>' http://127.0.0.1:9090/tailscale/logs
curl -i http://127.0.0.1:9090/tailscale/web
```

Expected result:

- unauthenticated API calls return `401`
- authenticated API calls return `200`
- Web shell returns `200`

With tsnet disabled:

- `/tailscale` reports `enable=false`, `state=disabled`, and `ready=false`
- `/tailscale/logs` returns an empty log list
- the Web page shows disabled state without inventing peers or gateway state
