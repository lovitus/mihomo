## Summary

This release adds a minimal Headscale control-plane fallback mechanism for environments where `tailscale.login-server` is a hostname but the embedded Tailscale control-plane resolver path cannot reliably reach it, such as some OpenWrt deployments.

It also fixes the GitHub Actions release workflow so the Go issue77930 patch step is idempotent. The previous `.23` tag passed tests but failed the Build workflow before release upload because the downloaded Go 1.26 toolchain already contained the patch.

## What Changed

- Added optional `tailscale.login-server-ip-fallbacks`.
- Fallback entries must be `http://` or `https://` URLs whose host is an IPv4 or bracketed IPv6 literal.
- Domain names are intentionally rejected in fallback entries to avoid adding DNS fallback behavior.
- Before creating `tsnet.Server`, mihomo probes IP literal candidates with `GET /key`.
- The first candidate returning HTTP `200` becomes `activeLoginServer` for the current run.
- If every IP candidate fails, mihomo keeps the original `login-server` and the existing startup grace behavior.
- `/tailscale` status exposes both the configured `loginServer` and the selected `activeLoginServer`.
- `-tailscale-wizard` reads the same fallback field and prints the selected active login server.
- The Build workflow now treats the Go issue77930 patch as already satisfied when reverse dry-run succeeds.

## Behavior Changes

Runtime behavior changes only when `tailscale.login-server-ip-fallbacks` is configured or when the GitHub Actions Go toolchain already includes issue77930.

- No change to persistent pin behavior.
- No change to proxy groups, rules, DNS, HTTP, DIRECT, or non-tsnet proxy behavior.
- No change to tsnet mesh SOCKS, gateway SOCKS, controller exposure, or UDP data path.
- No system DNS, mihomo DNS, environment proxy, or rule/proxy chain is used for fallback probing.
- No runtime control-plane migration is attempted after `tsnet.Server` starts.
- HTTPS IP fallbacks require the Headscale certificate to contain the IP address in SANs; mihomo does not rewrite Host or SNI.

## Config Example

```yaml
tailscale:
  enable: true
  login-server: http://headscale.example.com:8088
  login-server-ip-fallbacks:
    - http://192.0.2.10:8088
    - http://[2001:db8::10]:8088
  state-dir: tailscale
```

## Operational Notes

For OpenWrt or similar systems, use the wizard to verify registration independently of normal service logs:

```bash
mihomo -d /etc/openclash -f /etc/openclash/config/config.yaml -tailscale-wizard
```

If normal runtime logs do not show `[Tailscale]` messages, first check `log-level`; `warning` filters normal Tailscale `INFO` state logs.
